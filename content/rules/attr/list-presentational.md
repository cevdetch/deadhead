Five presentational attributes on lists are obsolete. `<ul type="square" compact>` is how lists were dressed before CSS. The attributes squeezed lists and picked bullets. They still turn up in old pages and in HTML generated by older tools.

## Why avoid

They are obsolete. The HTML Standard lists each spelling among the attributes that "are obsolete (though the elements are still part of the language), and must not be used by authors", with the instruction to use CSS list styling instead. Section 16.3 still backs them with reflected IDL across the list interfaces, which is live machinery: the attributes keep working as presentational hints in the weakest place in the author cascade, where any stylesheet rule for the same property wins.

So deleting one repaints the list wherever no stylesheet rule covers the property. Each attribute either does nothing, because CSS overrides it, or sets a value the stylesheet never states. Either way, part of the page design lives in markup, where nobody editing the CSS will look for it. MDN documents `compact` with a CSS `line-height` replacement and warns `type` away as deprecated with `list-style-type` as the replacement.

## Use instead

Move the list chrome to CSS and drop the hints:

```html
<ul>
  <li>First</li>
  <li>Second</li>
</ul>
```

```css
ul {
  list-style-type: square;
  line-height: 1.2;
  margin-left: 1.5rem;
}
```

## Detectability

Complete detection. The rule reports each element once, however many hints it carries. It checks `dl`, `ol`, `ul` and `li`, and nothing else. `type` on `ol` stays quiet: the HTML Standard keeps it conforming, to pick the marker "in the cases where that matters (e.g. because items are to be referenced by their number/letter)". There is no autofix: removing a live hint repaints the list, so the move to CSS needs a human look at the values.
