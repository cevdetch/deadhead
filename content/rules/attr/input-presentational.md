Four presentational attributes on `input` are obsolete: `align`, `border`, `hspace` and
`vspace`. `<input type="image" src="go.png" alt="Go" align="middle" border="1">` is how image
buttons were dressed before CSS, and the attributes still turn up in old pages and in HTML
generated by older tools.

All four came from the `img` element. An image button is an image that submits a form, so it
took the image's alignment, border and spacing attributes along with its `src` and `alt`.

## Why avoid

They are obsolete. The HTML Standard lists each spelling among the attributes that "are obsolete
(though the elements are still part of the language), and must not be used by authors", with the
instruction: "Use CSS instead."

What they still do depends on the control. The standard's rendering section maps them for "an
`input` element whose type attribute is in the Image Button state" and for no other kind of
input: `align` becomes `float` or `vertical-align`, `hspace` the left and right margins,
`vspace` the top and bottom margins, and a `border` greater than zero a solid border of that
width. On a text field, a checkbox or a submit button, nothing reads them, so
`<input type="text" hspace="10">` spaces nothing. `HTMLInputElement` still reflects `align` for
scripts.

On an image button the mapping is a presentational hint, the weakest place in the author
cascade: any stylesheet rule for the same property wins. So each attribute either does nothing,
because CSS overrides it, or sets a value the stylesheet never states. Either way, part of the
page design lives in markup, where nobody editing the CSS will look for it. MDN tabulates the
live `input` attributes with none of the four among them.

## Use instead

Move the styling to CSS and delete the attributes:

```html
<!-- Before -->
<input type="image" src="go.png" alt="Go" align="middle" border="1" hspace="8">

<!-- After -->
<input type="image" src="go.png" alt="Go" class="go">
```

```css
.go {
  vertical-align: middle;
  border: 1px solid;
  margin-inline: 8px;
}
```

The mapping is close, not exact. `align="middle"` aligns the middle of the image with the
baseline of the line, where `vertical-align: middle` aligns it with the baseline plus half the
x-height; `align="absmiddle"` is the value that maps to `vertical-align: middle`. `align="left"`
and `align="right"` float the button, so their CSS is `float`. On any other input type, delete
the attributes outright: they draw nothing.

## Detectability

Detectable with the selector alone. The CLI, the bookmarklet and the ESLint plugin report the
same findings, and none skips. The rule reports each `input` once, however many of the four it
carries, whatever its `type`. There is no autofix: removing a live hint repaints an image
button, so the move to CSS needs a look at the values.
