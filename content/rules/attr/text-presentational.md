Sixteen presentational attributes on text elements are obsolete. `<div align="center">`,
`<hr width="50%" noshade>` and `<br clear="all">` are how text was set before CSS: the
attributes aligned blocks, shortened and shaded rules, and cleared floats. They still turn up in
old pages and in HTML generated by older tools.

## Why avoid

They are obsolete. The HTML Standard lists each spelling among the attributes that "are obsolete
(though the elements are still part of the language), and must not be used by authors", with the
instruction: "Use CSS instead." Its implementation section still reflects them as properties,
such as `HTMLDivElement.align`, `HTMLHRElement.noShade` and `HTMLBRElement.clear`, and its
rendering section maps most of them to CSS as presentational hints.

The hints sit in the weakest place in the author cascade: any stylesheet rule for the same
property wins. So each attribute either does nothing, because CSS overrides it, or sets a value
the stylesheet never states. Either way, part of the page design lives in markup, where nobody
editing the CSS will look for it. Deleting one repaints the text wherever no stylesheet rule
covers the property.

The mappings are not one to one, which makes the move to CSS a matter of checking:

- `align` on `p` and `h1` to `h6` maps to `text-align`, and on `legend` to `justify-self`.
- `align` on `div` sets `text-align` and also aligns block children: the standard says a
  `div align="center"` is expected to "align descendants to the center", which `text-align`
  alone does not do for a child with a fixed width.
- `hr` maps `align` to its margins and `width` to `width`; `color` or `noshade` makes the
  border solid, and `size` sets the border widths or the height depending on which of those
  two is present.
- `br clear="all"` and `clear="both"` map to `clear: both`, `left` and `right` to their own
  values.
- `pre width` maps to nothing in the rendering section; the standard expects no style from
  it, and it survives as a reflected property.

## Use instead

Move the styling to CSS and delete the attributes:

```html
<!-- Before -->
<div align="center">
  <p>Centred text</p>
  <hr width="50%" noshade>
  <br clear="all">
</div>

<!-- After -->
<div class="centred">
  <p>Centred text</p>
  <hr class="half">
  <br class="clear">
</div>
```

```css
.centred { text-align: center; }
.centred > * { margin-inline: auto; }
hr.half { width: 50%; border-style: solid; }
br.clear { clear: both; }
```

The `margin-inline: auto` line reproduces what `div align="center"` did to block children with a
width of their own; drop it if the container holds text alone. A `<br clear>` that ended a run
of floated images can give way to `clear` on the next block, or to a container that holds its
floats with `display: flow-root`.

## Detectability

Detectable with the selector alone. The CLI, the bookmarklet and the ESLint plugin report the
same findings, and none skips. The rule reports each element once, however many hints it
carries. It checks `div`, `p`, `h1` through `h6`, `legend`, `pre`, `hr` and `br`, and nothing
else; table attributes belong to `attr/table-presentational`. There is no autofix: removing a
live hint repaints the text, so the move to CSS needs a look at the values.
