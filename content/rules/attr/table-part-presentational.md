Presentational attributes on `caption`, `col`, `thead`, `tbody`, `tfoot`, `tr`, `td` and `th` are obsolete. `<td align="center" bgcolor="#ffffff" nowrap>` is how cells were dressed before CSS. The attributes aligned text, colored rows and froze wrapping. They still turn up in old pages and in HTML generated by older tools.

## Why avoid

They are obsolete. The HTML Standard lists each spelling among the attributes that "are obsolete (though the elements are still part of the language), and must not be used by authors", with the instruction: "Use CSS instead." Section 16.3 still backs them with reflected IDL across the table interfaces, which is live machinery: the attributes keep working as presentational hints in the weakest place in the author cascade, where any stylesheet rule for the same property wins.

So deleting one repaints the table wherever no stylesheet rule covers the property. Each attribute either does nothing, because CSS overrides it, or sets a value the stylesheet never states. Either way, part of the page design lives in markup, where nobody editing the CSS will look for it. MDN files the cell hints under deprecated attributes, each paired with its CSS property, and marks `char` and `charoff` as doing nothing.

## Use instead

Move the cell chrome to CSS and drop the hints:

```html
<table>
  <tr><td>Basic</td><td>CHF 9</td></tr>
</table>
```

```css
td {
  text-align: left;
  vertical-align: top;
  background-color: #fff;
  white-space: normal;
}
```

## Detectability

Complete detection. The rule reports each element once, however many hints it carries. It checks `caption`, `col`, `thead`, `tbody`, `tfoot`, `tr`, `td` and `th`, and nothing else. There is no autofix: removing a live hint repaints the table, so the move to CSS needs a human look at the values.
